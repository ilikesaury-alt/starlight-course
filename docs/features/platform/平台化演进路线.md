# 从「桌面版应用」到「小学生个人学习平台」—— 演进路线

> 状态：2026-11-15 立项诊断。本文只定方向与分期，不含实现细节。
> 依据：本仓 `electron/main.cjs`、`src/store/useCourseStore.ts`、`src/pages/*`、`docs/features/desktop/` 的实际代码与文档，不是凭印象。

## 1. 一句话诊断

**它现在是一个「内容很厚、装进窗口的单用户网页应用」，还不是平台。**

内容和教学设计已经是这个项目最强的部分（96+96 课、96 篇小故事、SRS、听写阶梯、TTS 七级兜底），
短板**不在内容，在产品的四根地基柱**：身份、数据、节律、原生。这四根现在都是空的或临时的。

判据很硬：**卸载重装 = 进度清零，且没有任何导出/导入功能**
（`docs/features/desktop/桌面化-交付文档.md` §5 第 5 条自己写着「无导出/导入功能」）。
一个孩子用了半年的学习数据，一次误操作就没了 —— 这不叫平台，叫试用装。

## 2. 现状盘点（代码事实，非推测）

| 维度 | 现状 | 平台该有的样子 |
|---|---|---|
| 数据存储 | 全部在 `localStorage`（zustand persist，`name:'starlight-course'`，`version:8`） | 落盘到用户目录的结构化文件，可备份、可迁移、可被原生层读写 |
| 桌面原生能力 | `electron/main.cjs` **无 preload、无 `ipcMain`、无 `contextBridge`**（实测 grep 命中 0 次） | 主进程与前端有受控通道，能做文件、托盘、自启、更新 |
| 身份 | 全局单份进度，无「这是谁在学」的概念 | 至少一份「孩子档案」，为多孩/换机留出位置 |
| 角色 | 孩子和家长看同一套界面；`Progress.tsx` 里直接摆着「清空全部进度」按钮 | 孩子看任务和玩，家长看设置、报告、数据管理 |
| 每日节律 | `TodayTasks` 是「推荐今天做什么」，不是「今天要做完什么」；无目标、无时长、无完成闭环 | 有计划、有进度、有「今天做完了」的收束 |
| 分发 | 手工打包 NSIS，用户自己重装；无 `electron-updater` | 应用内提示更新，静默升级 |
| 入口 | 首页硬编码 7 个模块宫格，随内容增长会继续膨胀 | 入口由数据驱动，模块可增删而不改首页代码 |

**这些不是「不够好看」，是「结构上还撑不起平台」** —— 换句话说，再往里堆内容，边际收益会越来越低。

## 3. 分期路线

原则：**每一期单独交付、单独可用，不做「全部做完才能用」的大爆炸改造。**
每期都必须保持既有 e2e 契约与 PWA 网页版不回归（这是本项目一贯的硬约束）。

### P0 · 数据主权 + 身份地基（最高优先级）

**为什么先做这个**：它是唯一「不做就会持续损失」的一期。孩子的每一分钟学习都在往一个
卸载即失的 localStorage 里写。且它同时是 P1（角色）、P2（原生）、P3（报告）的共同前置。

- 引入 `electron/preload.cjs` + `contextBridge`，只暴露**白名单**能力（不开 `nodeIntegration`）
- 主进程增加 `ipcMain` 处理器：读/写 JSON 数据文件，落盘到 `app.getPath('userData')`
- 数据层做**适配器**：桌面版走文件，网页版继续走 `localStorage`（网页版不能回归）
- **一键导出 / 导入备份**（`*.starlight.json`），家长在界面上能自己操作
- 首次启动把既有 `localStorage` 数据**自动迁移**进文件，不丢进度（吸取 §5 第 1 条的教训）
- 引入「孩子档案」最小形态：`profileId` + 昵称 + 头像，先支持单档案但结构上留多档位

**验收**：装一次 → 学一课 → 导出 → 卸载重装 → 导入 → 进度、星星、SRS 全部还原。

### P1 · 角色分离 + 每日节律

- **孩子视图**：只留「今天做什么」+ 玩。去掉所有危险操作与配置项
- **家长视图**：设置、报告、数据管理（导出/导入/重置）集中收口，`Progress` 里的清空按钮移走
- **每日计划**：从「推荐」升级为「今日清单」—— 到期复习 + 1 课新课 + 1 篇阅读，可完成、可收束
- 完成闭环：做完给出明确的「今天完成了」状态，而不是无限滚动的内容列表

**验收**：孩子端 5 秒内知道「现在该点哪个」；家长端 3 步内能备份或重置。

### P2 · 桌面原生能力

- **系统托盘常驻** + 开机自启（学习工具要「随手就开」，而不是找图标）
- **自动更新**（`electron-updater` + NSIS 差量），家长不用手动重装
- **离线发音包**：把当前依赖网络的 TTS 链路，对已学词做本地缓存，弱网也不哑
- 桌面版专属：打印/导出学习报告为 PDF

**验收**：断网启动可用；新版本发布后应用内可完成升级。

### P3 · 成长报告

- 周报 / 月报：学习时长、掌握曲线、错题收敛趋势
- 可打印的一页纸（家长会/老师沟通用）
- 报告数据全部来自 P0 的文件层，不再现算

## 4. 不建议做的事（避免走偏）

- ❌ **不要为了「平台感」加账号体系 / 云同步**：这是个人学习工具，本地优先才是它的优势。
  云端只该是「备份的一种出口」，不该是使用前提。
- ❌ **不要重写视觉**：现有视觉体系（暖纸色、模块主题色、儿童向字号）已经跑通并有 e2e 钉住。
  平台化是结构演进，不是换皮。
- ❌ **不要一次改 store**：`useCourseStore` 的 `version:8` + `migrate` 是进度不丢的生命线，
  任何结构变更都必须走迁移链，不能推倒重来。

## 5. 建议的第一刀

如果只做一件事，做 **P0 的「数据落盘 + 导出/导入」**，且先做导出/导入这一半：

- 它不依赖 preload/IPC 的完整改造（网页版也能用 `Blob` 下载 + `FileReader` 导入）
- 它立刻消除「进度会丢」这个最大的用户风险
- 它是后续所有数据层改造的**安全网** —— 有了导入导出，再动 store 结构就不怕了

之后再补 preload + IPC + 文件落盘，把「导出/导入」从手动变成自动。
