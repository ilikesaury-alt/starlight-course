# Starlight 少儿英语学习 App — UI 交互体验审查报告

> 审查目标：以**小学生 / 学龄前儿童**为主要用户，逐项评估现有实现，定位可优化点并给出可落地的具体建议。
> 审查范围：当前仓库 UI 层（SCSS 设计令牌、公共组件、页面、导航、错误处理）。
> 审查方法：通读源码 + 关键文件逐行核对（引用 `文件:行号`）。
> 技术背景：React 18 + Vite + SCSS 设计令牌；纯前端 PWA，HashRouter；全站以 **emoji + 点击** 驱动，无自由文本输入。

## 一、总览（各维度风险等级）

| 维度 | 现状评分 | 主要风险 | 优先级 |
|------|---------|---------|--------|
| 1. 操作简化（按钮/点击区/步骤） | 中 | 最高频控件 `.speak-btn` 仅 38px，低于 44pt 规范 | 🔴 P0 |
| 2. 视觉设计（配色/图标/字体） | 良 | 移动端 12px 次要文字偏小；浅色单元主色对比度存疑 | 🟡 P1 |

| 5. 导航结构（层级/返回/可达性） | 良 | 5 个课程模块不在底部导航；无面包屑；3 层略深 | 🟡 P1 |

## 1. 操作简化：按钮大小、点击区域、交互步骤

### 现状（好的一面）
- 按钮统一走 `btn-base` 混合：圆角药丸、加粗、`:active` 缩放反馈，按压手感一致（`_components.scss` + `_mixins.scss`）。
- 底部导航 `.bottom-nav-item` 约 53px 高、大 emoji+大字号，拇指友好（`_components.scss:80-96`）。
- 单词卡整词可点、整卡可点，命中区域大（`_study.scss` `.fc-word`）。

### 存在的问题
1. **`.speak-btn` 仅 38×38px，是全站最高频控件却低于规范。**
   ```scss
   .speak-btn { width: 38px; height: 38px; }   /* _components.scss:289-290 */
   ```
   每个单词、每道选项都带一个发音按钮，儿童手指易误触相邻元素。Apple HIG 建议 ≥44pt，Material 建议 ≥48dp。
2. **小按钮/小标签仍偏矮**：`.btn--sm` padding `8px 14px`、字体 15px ≈ **31px 高**（`_components.scss:167`）；错题本"✅ 掌握"用 `.mastery-btn` padding `8px 16px` ≈ **31px 高**（`WrongBook.tsx:79`）。
3. **全站无统一 `min-height` 下限**：点击区完全由 `padding + font-size` 决定，小屏上不可控。
4. **控件偏多**：单词卡一行排了 🔊 + 🐢慢速🔊 两个发音钮（`LessonPreview.tsx:154-155`），加上"上一个/下一个"两个按钮和圆点，单屏操作点偏密。

### 优化建议
- **🔴 立刻**：把 `.speak-btn` 改为 `44–48px`（建议 46px），并保留 `gap` 防止贴边（`_components.scss:289-290`）。
- **🔴 立刻**：给 `.btn` / `.btn--sm` / `.mastery-btn` / `.chip` 统一加 `min-height: 44px`（关键操作建议 48px；`_components.scss`、`.mastery-btn`）。
- 把"慢速🔊"与正常🔊 合并为**双状态**（如普通点击正常速、长按出慢速），减少单词卡控件数。
- `.lesson-pill` / `.fc-dot` 等小圆点保持视觉小、但用 `padding`/`::before` 把**可点区域扩到 ≥44px**。

## 2. 视觉设计：配色、图标文字、字体大小

### 现状（好的一面）
- 核心调色板集中在 `_tokens.scss`（天蓝/暖黄/嫩绿/粉/葡萄紫/珊瑚），童趣强、且为单一真源（`_tokens.scss:10-80`）。
- emoji 作图标使用一致且直观：🔊=发音、⭐=星星、🏠=首页。
- 模块化主题色架构良好：`moduleThemeVars()` 由单色派生整套 `--brand*/--mc*`，页面根套用即全量换肤（`src/utils/theme.ts`）。
- 大屏（≥1024px）整体放大字号令牌，照顾远距离阅读（`_responsive.scss`）。

### 存在的问题
1. **移动端 12px 次要文字偏小**：`--fs-xs: 12px`（`_tokens.scss:94`）用在 `.badge`、`.label`、`.stat-label`、`.page-kicker`、`.module-num` 等标签/状态；而放大规则只在 ≥1024px 生效（`_responsive.scss`），**手机（主使用场景）的 12px 文本不变**。
2. **个别硬编码字号绕过令牌**：`WrongBook.tsx:47` 写死 `fontSize:'13px'`，不随响应式放大。
3. **对错反馈仅靠颜色**：测验选项正确=绿底、错误=红底（`QuizEngine` 的 `.correct/.wrong`）；对色觉差异儿童不友好。
4. **每单元主题色写死在 data 文件**：`starlight.ts` 12+ 单元各有不同主色 hex（如 `#84cc16` 浅绿、`#0ea5e9` 浅蓝），配白字时部分对比度偏低，儿童可能读不清。

### 优化建议
- **🟡 把 `--fs-xs` 提到 13–14px、`--fs-sm` 提到 14–15px**（作为移动端新基准），桌面仍按 `_responsive.scss` 放大；并移除 `WrongBook.tsx:47` 的硬编码 `13px`。
- 对错反馈**增加形状/图标差异**：✓ 对勾 + ✗ 叉、或圆形/叉形外框，不依赖颜色 alone。
- 对每单元主题色做一次 **WCAG AA 对比度校验（≥4.5:1）**，浅色单元主色加深或改用深色文字。
- 课程入口卡片副标题过长（如 `Home.tsx:44` 整句），可精简为 4–8 字短语，减少低龄注意力分散。

## 3. 反馈机制：视觉 / 音效反馈是否明确

### 现状（好的一面）
- 发音三级回退：英文 Kokoro(WebGPU)→有道→speechSynthesis；中文 Edge TTS→有道→speechSynthesis；儿童慢速 `rate=0.6`（`src/utils/speak.ts`）。
- 全局单一发音器 + 12s/18s 安全定时器，🔊/⏸ 状态永不卡死（`speakerControl.ts`）。
- 播放中有 `speak-pulse` 动画 + 图标切换（`SpeakButton.tsx:36,41`）；`.fc-word` 有 `word-pulse`；测验答对 `correct-pop`、答错 `shake`（`_study.scss`）。
- 完成奖励星星 `addStars()`；进度点填充反馈。

### 存在的问题
1. **🔴 TTS 全失败时静默无提示**：`speak.ts` 各 catch 全部静默，若所有发音层都失败，按钮"点了没反应"，儿童无法判断是网络问题还是坏了，也没有"再试一次"入口。
2. **庆祝动效未接入**：`.confetti-container` 样式已定义却从未被实例化（`_study.scss:344`）——全对/单元完成的 confetti 缺失。
3. 部分操作（标记掌握、上一课/下一课）仅靠 `:active` 缩放，缺少"已执行"的明确状态保持。

### 优化建议
- **🔴 立刻**：TTS 全失败时，`SpeakButton` 显示轻量提示（按钮抖动 + toast「声音没出来，点一下再试试～」），不要静默吞掉。
- **🟡 接入 confetti 庆祝动效**到测验全对 / 单元完成（样式现成，仅缺挂载）。
- 关键操作增加"完成态"保持（如"已掌握✓"高亮约 1 秒再收起），强化"我做到了"的反馈。

## 4. 防误触设计：关键操作确认 / 不可逆保护

### 现状（好的一面）
- 两个不可逆的批量操作已有确认：`WrongBook.tsx:99` 清空全部错题、`Progress.tsx:75` 重置全部进度。

### 存在的问题
1. **🔴 确认弹窗是原生 `window.confirm()`**：系统弹窗按钮极小、纯文字、阻塞 UI，对低龄儿童完全不友好；且 `resetAll`/`clearWrongWords` 经 zustand `persist` 写入 localStorage，**不可逆**。
2. **单条删除无确认**：错题本"✅ 掌握"直接 `removeWrongWord`（`WrongBook.tsx:80-85`）；SmartReview 答对时自动 `removeWrongWord`（`SmartReview.tsx`），误触即丢失该错题记录。
3. **🔴 中途退出无守卫**：做题/学习中点"下一课""返回课程列表"立即路由跳转，无"正在学习中，确定离开吗？"提示，儿童误触会丢失本次做题进度（SRS 已播种子，但本次计数丢失）。
4. 全站**无自定义确认弹窗组件**，只有原生 confirm。

### 优化建议
- **🔴 立刻**：用自研**大按钮 + emoji + 童语**确认弹窗替换 `window.confirm`，文案如「确定要清空吗？清空后找不回来哦 🧹」，取消/确定都做成大按钮。
- 对"已掌握/移除错题"等单条不可逆操作，提供 **3 秒可撤销**（toast「已移除 ✓ 撤销」）或二次确认。
- **🔴 立刻**：测验/学习进行中加**离开确认**（特别是做到一半点返回/下一课）。
- 危险操作（重置/清空）可加"按住 1 秒确认"或两步确认，进一步降低误触。

## 5. 导航结构：层级深度 / 返回路径 / 可达性

### 现状（好的一面）
- HashRouter；底部固定 3 tab（🏠首页 / 🔤字母 / 📊进度），大图标大字（`Layout.tsx:22-36`）。
- 每个深层页都有顶部返回按钮 + 底部 `back-link` + 上/下一课，路径基本清晰（`LessonPreview.tsx:105-123` 等）。
- 最大层级 3 层（首页 → 模块 → 单元 → 课），不算过深。

### 存在的问题
1. **5 个课程模块都不在底部导航**：语文/英语/Starlight/FlyGuy/RocketGirl 仅能从首页卡片进入（`Home.tsx`）。儿童从"字母/进度"页想切到某课程，必须先回首页再点，多一步。
2. **无面包屑**：仅靠"返回课程列表 / 返回首页"文字链接；低龄儿童可能分不清二者。
3. **3 层对低龄略深**，且"上一课/下一课"是**页间路由跳转**（整页刷新式），连续学习时每次回到新页面重新加载，节奏被打断。
4. 课程入口卡片信息密度高（长副标题），易分散注意。

### 优化建议
- **🟡 底部导航增加"课程"聚合入口**（或汉堡菜单），让 5 个模块一级可达，减少回首页次数。
- 关键学习页加**轻量面包屑**（首页 › 模块 › 单元），用图标+短词，不用长句。
- 单元内连续学习用**同页 state 切换"下一课"**而非路由跳转，保持沉浸、不打断。
- 课程入口副标题精简为短语（见 §2）。

## 6. 容错处理：输入限制 / 错误提示 / 童语

### 现状（好的一面）
- 全站纯点击驱动、无自由文本输入，因此**无输入校验类问题**——对儿童是正确选择。
- `SafeBoundary` 错误边界包裹各区块；全局 speech 错误守卫防 React 崩溃（`main.tsx` + `speechGuard.ts`）。
- 现有 empty/错误文案已较童趣（"错题本是空的，太棒啦"、"没有找到这个模块"）。

### 存在的问题
1. **🔴 `SafeBoundary` 出错渲染 `null` 白屏，无兜底**：`App.tsx` 整路由树包 `SafeBoundary` 且**未传 `fallback`**（`SafeBoundary.tsx:31` 默认 `null`）；任意页面抛错 → 整屏空白、无提示、无返回入口。页面级 SafeBoundary 也多未传 fallback。
2. **现成的错误样式被浪费**：`.safe-boundary` / `.route-error`（`_components.scss:309-313`）本可显示"哎呀出错了 🛠️ 点这里回家"的童趣卡片，但 SafeBoundary 返回的是 `null`，从未接上。
3. `componentDidCatch` 为空，错误被静默吞掉（不影响儿童，但不利于长期修复）。
4. TTS 失败无提示（见 §3）。

### 优化建议
- **🔴 立刻**：给所有 `SafeBoundary` 加默认 `fallback`，接上现成的 `.route-error` 童趣卡片（🛠️ + "哎呀，页面打个盹儿了，点这里回首页" + 返回按钮），`App.tsx` 层也加全局兜底。
- TTS 失败加童语提示（见 §3）。
- 保持纯点击、无文本输入设计；若未来加跟读录音等，用**受控选择**而非自由输入。
- 保留 dev 环境 `console.error` 上报，但 UI 对儿童一律友好化。

## 三、优先行动清单

1. `.speak-btn` 38→46px（`_components.scss:289-290`，一行）。
