# 英语学习路线调研与开源方案参考

> 整理自 2026-09-29 的对话：项目概览 + 学习路线诊断分析 + GitHub 开源项目调研。
> 研究对象：8 岁孩子的英语路线（little fox 分级动画 + 动画音频循环熏听 + basic reading 刷单词 + 菲教 Starlight 课）。
> 核心诉求：上课（Starlight 菲教 1v1，每节 25 分钟，主攻听说）时经常无法组织语言、卡住不知如何表达。

---

## 0. 术语与假设说明

- **「rag」按 RAZ（Reading A-Z / Raz-Kids 分级阅读）理解**——与 little fox、basic reading 同类的分级读物，以整句阅读著称，与「句子积累」假设吻合。若实际指其他资源，需重调结论。
- 本项目（starlight-course）是配套 Oxford Starlight Starter（预备级）的**纯前端 PWA**，React18+TS+Vite+Zustand+Tailwind，HashRouter，vite-plugin-pwa 离线，进度存 localStorage（zustand persist，version 6 + migrate）。
- 五大内容模块（注册表 `src/data/modules.ts`）：`starlight`（主课 12 单元 96 课）、`flyguy`/`rocketgirl`（故事）、`chinese`（三年级上语文）、`eng3a`（三年级上英语外研版）。
- 关键机制：Leitner 5-box SRS（`src/data/srs.ts`）、星星规则（`src/utils/stars.ts`，全对=5/≥80%=3/参与=1，≥80% 通关）、统一闯关结算（`useSettleQuiz`）。

## 1. 学习路线诊断：未坚持 RAZ 是否导致课堂卡壳？

### 1.1 结论（一句话）

方向**基本正确，但根因比「没刷 RAZ」更广**：孩子路线是「听 + 认单词」的纯输入型，缺了**整句输入的内化**和**被推动的口语输出**两块。RAZ 是补前者的好工具，但不是唯一解；光补 RAZ 不补输出，课堂照样可能卡壳。

### 1.2 现有路线的本质

| 现有动作 | 性质 | 产出 |
|---|---|---|
| little fox 分级动画 + 音频循环熏听 | 可理解性输入（听） | 听力、语感 |
| basic reading 刷单词 | 词汇识别（词级） | 孤立单词 |
| 菲教 Starlight 课 | 期望「communicate」输出 | ——（卡在 communicate） |

阅读侧停留在「单词」而非「整句」，整条路线 **input-heavy**。

### 1.3 理论依据

- **Swain 输出假说（1985）**：来自加拿大法语沉浸班追踪——学生听几年法语、理解力接近母语，但开口仍满语法错、只会说 1–2 词短句。原因：听懂时大脑靠上下文猜、走捷径；**说出一句话才逼你做上千个语法决策**。听，永远不逼你做这些决策。
- **Noticing gap（注意缺口）**：孩子「卡住、不知如何表达」，正是真要开口时才发现脑子里没有现成句子 schema；纯输入路线永远不会暴露这个缺口。
- **公式化语块（formulaic sequences）**：研究（Nation / Ellis / Kormos）一致指出，口语流利度底层是把 "I want a ___." 这类整句当「一块」存进心理词库，开口时整块提取，不必临时拼装。
- **Krashen 输入假说 ↔ Swain 输出假说**：现代共识二者互补——输入建词汇/语感/语法直觉（应占大部分时间），输出练「能用出来」的三机制（noticing / hypothesis testing / syntactic processing）。只做输入的人 = 听得懂但被问就僵。

### 1.4 RAZ 具体补了什么

RAZ 是分级整句读物，核心句型在各级**高频复现（复现率 70%+）**。your basic reading 给「砖（单词）」，RAZ 给「带砂浆的句子模板」。只刷单词不刷整句 = 有砖没图纸。

### 1.5 根因澄清与置信度

- 成立且符合理论：缺的是「**整句级输入的内化 + 被推动的输出练习**」，RAZ 是补前者的最佳载体之一，非唯一解（little fox 剧本、Starlight 课文都能当整句素材）。
- 无法 100% 归因：8 岁孩子在菲教 1v1 卡壳，也可能有「输出焦虑 / 没人逼他说整句」因素——这两块要一起补。
- **置信度**：方向高；精确机制中高。

## 2. 针对 Starlight 的补充学习方案

Starlight Starter 官方路线 **engage → practice → communicate**，孩子卡在 communicate，说明前两步没在家打好底。方案核心：**把现有三件套升级为「整句输入」，再补「课前输出」，让课堂变成「表演」而不是「第一次开口」**。

### 2.1 改造现有输入（不动路线，只改用法）

| 现有动作 | 改造为 | 依据 |
|---|---|---|
| little fox 只看/只听 | **跟读（shadowing）**：每集挑 3–5 句暂停后原句跟说；音频循环里加「留白跟说」一遍 | 主动提取比被动听更自动化（Nation：retrieval 才 automatize） |
| 熏听循环 | 循环里留空让孩子接话（听半句、说后半句） | 把 input 变成 pushed output 雏形 |
| basic reading 刷单词 | **单词挂在 Starlight 句子框架里学**，不孤立背。如 car → "I want a car." | 词进 frame 才是可产出的 |

### 2.2 句子框架库（最该补的「mortar」）

把 Starlight 12 单元关键句抽成**可填空框架**，当整体练（不是学语法）：

| 单元 | 核心框架（替换词、保框架练） |
|---|---|
| 1 问候/颜色 | Hello! / How are you? / My name is ___. / What color is it? → It's ___. |
| 2 动物 | What's this animal? → This is a ___. / What animal do you see? → I see a ___. |
| 3·8 食物/喜好 | Do you like ___? → Yes, I do. / No, I don't. / What do you want? → I want ___. / I'd like ___. |
| 4 玩具/能力 | Which ___ do you want? → I want a ___. / Can you ___? → Yes, I can. / Here you are. Thank you. |
| 5 反义/状态 | It's ___. / Is it ___? → Yes/No. / I'm ___(happy/sad). |
| 6 身体 | Touch your ___. / I have ___. / What can you do? → I can ___. |
| 7 家 | There is a ___. / Is there a ___? / This is my ___. |
| 9 一天 | I like ___ for breakfast. / It's time to ___. |
| 10 生日 | I need ___. / Here is a ___ for you. |
| 11 地点 | Where do you want to go? → I want to go to ___. / I like ___ (playing…). |
| 12 交通 | How do you go to ___? → I go to ___ by ___. / Turn left/right! |

练法：每单元只抓 3–4 个框架，**替换词、保框架**（car→bus→ball），即公式化流利度训练。

### 2.3 补「课前输出」（关键，否则课堂仍是第一次开口）

- **课前 5 分钟暖场**：用当周单元框架，家长问、孩子答整句。目标——上课前框架已「长在嘴边」。
- **家庭角色扮演**：照搬单元情境。Unit 4 玩具→摆玩具店："Which toy do you want? I want a car. Here you are. Thank you."；Unit 11 地点→"Where do you want to go? I want to go to the zoo."
- **与菲教对齐**：请老师**不接受单词级回答，逼整句**（"Can you make a full sentence?"）。Swain 指出课堂常纵容孩子用 1–2 词混过去，正是卡壳不被纠正的原因。
- 低压力输出可用 AI 口语陪练，或**本 App 的 SmartReview + SpeakButton**——已把 Starlight 单词种进 SRS，让他**对着卡片「说出整句」**而非只认词，是现成每日口语 drill。

### 2.4 每周节奏（可执行）

- **每天**：1 集 little fox（听）+ 1 遍跟说 + 5 分钟 RAZ（或 Starlight 课文）整句朗读
- **课前一天**：10 分钟框架暖场（对应单元）
- **课后**：SmartReview 口头刷 + 用 1 句话说今天学了啥
- **每周**：1 次家庭角色扮演

### 2.5 避坑

- 别只靠 RAZ 或只靠听——**输入整句 + 输出练习必须双管**，否则理论上一半问题没解决。
- 别一上来纠正语法，先求「能整句说出」，准确率靠复现自然上来（hypothesis testing 靠反馈，不是打断）。
- 8 岁用 Starter 不算超纲，卡壳是「输出练得少」不是「级别错」，不用急着换教材。

## 3. GitHub 开源项目调研（结构化结论）

筛选标准：与本项目（少儿英语 PWA / Leitner SRS / 单词卡 / 阅读习得 / 浏览器 TTS）相关，且有可借鉴价值。

### 3.1 open-spaced-repetition/ts-fsrs（FSRS 间隔重复算法）
- **核心思路**：ML 训练的「自由间隔重复调度器」替代 Leitner/SM-2，基于 D(难度)/S(稳定性)/R(可提取性) 动态算下次复习；宣称比 Anki 默认留存高 20%、同等留存工作量少 30–40%。
- **架构设计**：纯 TS、零依赖、ESM/CJS/UMD 多格式；`FSRS` 类无状态，`repeat(card, now)` 一次算 4 种评分的 what-if；参数优化在独立 Rust binding，运行时仅轻量调度（微秒级/卡，~1KB）。
- **亮点**：难度随个人表现自适应；复习触发 R≈0.9；浏览器/Node 通用，MIT。
- **借鉴 + 场景**：**直接替换本项目 Leitner 5-box 调度**（`src/data/srs.ts` 的 `scheduleNext`），保留 localStorage 持久化与 migrate，只换内核。★优先级最高。

### 3.2 LuteOrg/lute-v3（Lute — 通过阅读学语言）
- **核心思路**：导入外语文本，阅读时点生词查词典建档，词按熟悉度着色；强调「阅读即习得」。
- **架构设计**：Python/Flask 自托管；term + parent term（habló→hablar 词形关联）+ 图片 + 多词术语。
- **亮点**：parent term 词族复用；单词状态分级着色；可导出 Anki；数据本地自托管。
- **借鉴 + 场景**：**借鉴「阅读即习得 + 词状态可视化」，对应「RAZ/整句输入缺口」**。可加「课文点读→自动入卡」流程，把 Starlight 课文做成可点读文本。**只取产品思路，不取 Python 技术栈**（本项目纯前端实现）。

### 3.3 JiayuanZhu/背单词小助手（儿童向 PWA）
- **核心思路**：儿童 PWA 背单词，简化艾宾浩斯曲线智能复习，离线可用。
- **架构设计**：纯前端 PWA + GitHub 作云存储实现多设备/家人共享；内置「标准/快速/缓慢」三档复习间隔、连续打卡、学习目标。
- **亮点**：儿童友好 UI；可装主屏离线；GitHub 当免费云同步零服务器；间隔档位可切。
- **借鉴 + 场景**：**作「儿童 PWA 范式」标杆**。借鉴「复习节奏档位」做设置项；借鉴「GitHub/公共云轻量同步」解决换设备丢进度（当前 `resetAll` + 单设备 localStorage 是痛点）。

### 3.4 kongpemg1212/english-learning-app（AI 跟读 + 双模式 PWA）
- **核心思路**：成人备考 + 少儿对话双模式；少儿含关卡地图/拼读/拖拽；成人含 shadow reading。
- **架构设计**：Vue3 + Tailwind + Web Speech API（TTS/STT）；SQLite 导出 JSON 供前端秒加载；PWA 离线优先；GitHub Gist 同步（开发中）。
- **亮点**：**Shadow Reading 实时语音识别 + 发音置信度打分对照原声**；翻译遮罩主动回忆；零外部 API、离线 resilient。
- **借鉴 + 场景**：**直击「输出卡壳」——做每日跟读 drill**。本项目已有 SpeakButton + SmartReview SRS，缺「孩子开口说整句并获反馈」。加跟读模式：播 Starlight 关键句→Web Speech Recognition 跟读→文本/置信度反馈。技术复用现有 Web Speech API。

### 3.5 xialeistudio/echoic（逐句跟读 + 音素级发音评分）
- **核心思路**：导入音频→逐句跟读→准确度/流利度/完整度三维评分，细化到单词和音素。
- **架构设计**：React18 + FastAPI；ASR=WhisperX，评分=本地 wav2vec2+phonemizer（数据不出本机）；Docker 一键起；音素按得分着色。
- **亮点**：0.5×–2× 调速 + 原声/录音 A/B 对比；音素级着色定位弱点；本地模型免云 API 费与隐私顾虑；单词复盘汇总弱点。
- **借鉴 + 场景**：**借鉴「逐句跟读 + A/B 对比 + 音素着色」交互范式**做口语练习 UI。后端 ML 过重——**只取 UX 范式，发音评分先用浏览器 Web Speech Recognition 轻量版**，重 ML 作可选增强。

### 3.6 react-speech-kit / react-text-to-speech（浏览器语音 React 封装）
- **核心思路**：把原生 SpeechRecognition 与 SpeechSynthesis 封装成 React hooks/组件。
- **架构设计**：`useSpeechSynthesis`（rate/pitch/voiceURI 可调、onEnd）、`useSpeechRecognition`（onResult 流式、lang）；`react-text-to-speech` 额外支持实时文字高亮、长文本分块、多实例、卸载自动清理。
- **亮点**：内置 `supported` 守卫防不支持浏览器报错；实时高亮跟读；错误/生命周期事件全；卸载自动 cancel 防泄漏。
- **借鉴 + 场景**：**重构 `SpeakButton.tsx` 与 `speak*.ts`**。现有「三层错误兜底」偏手写，可改用成熟 hook + 实时高亮（跟读逐词亮起）+ `supported` 守卫 + 卸载清理。★中优先级。

### 3.7 Goutam990/ALFREDTASK（Leitner Flashcard 参考实现）
- **核心思路**：标准 Leitner 5 箱，答对进下一箱、答错回箱 1。
- **架构设计**：React18+TS+Tailwind+Framer Motion+Supabase；箱间隔 Box1=1天/2=2/3=5/4=8/5=14天。
- **亮点**：明确箱→天数映射；乐观更新；只取到期卡。
- **借鉴 + 场景**：**仅借其「箱间隔数值」做本项目 Leitner 调参参考**（当前间隔未公开细节，可用 1/2/5/8/14 校准）。其 Supabase 后端**不采纳**——与纯前端离线定位冲突。

### 3.8 综合映射（短板 → 仓库 → 落地）

| 短板（来自 §1/§2） | 可借鉴仓库 | 落地动作 |
|---|---|---|
| SRS 调度不够个性化 | ts-fsrs (#3.1) | 换 `scheduleNext` 内核，保留持久化 |
| 缺整句/阅读输入内化 | Lute (#3.2) + 背单词PWA (#3.3) | 课文点读 + 阅读入卡 + 复习档位 |
| 课堂输出卡壳 | echoic (#3.5) + english-learning-app (#3.4) | 加「逐句跟读 + 调速 + A/B」模式 |
| SpeakButton 自维护重 | react-speech-kit (#3.6) | 改成熟 hook + 实时高亮 |
| 换设备丢进度 | 背单词PWA (#3.3) | GitHub/公共云轻量同步 |

### 3.9 明确不采纳项

- Lute 的 Python/Flask 后端、各 Leitner 项目的 Supabase/Express 后端——与本项目「纯前端 PWA、零服务器」定位相悖。
- 本项目离线架构本身更契合单孩家用、零运维场景，应**保持**，只吸收产品思路与前端实现范式。

## 4. 下一步可选动作

1. **FSRS 替换**（#3.1）：最小改动升级 SRS 内核，收益最高。
2. **跟读模式原型**（#3.4/#3.5）：利用现有 Web Speech API + SmartReview，加「逐句跟读 + 调速 + A/B」解决输出卡壳。
3. **句子框架卡**：把 §2.2 的 12 单元框架做成可练 SRS 卡（挂到 starlight 模块）。

5. **轻量云同步**：参考 #3.3 用 GitHub/公共云解决换设备进度丢失。
